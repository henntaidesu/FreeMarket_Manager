# 网页蓝牙连接德佟标签机打印发货码 —— 解决方案

> 目标：在 `/#/todos` 页面把「已打包」订单的发货二维码 / 条形码，通过**网页蓝牙**直接发送到**德佟（Detonger）标签打印机**打印。
> 覆盖端：PC（Win/Mac/Linux）、Android、iPad、iPhone。

---

## 一、调研结论（先看这三条，决定架构）

### 1. 【致命约束】iOS 普通浏览器不支持网页蓝牙
Web Bluetooth API 在 **iOS 全部浏览器**（Safari / iOS 版 Chrome / Edge）上都**不支持**，因为 Apple 强制所有 iOS 浏览器用 WebKit 引擎，WebKit 至今（2026 / iOS 18）未实现。这是**政策限制，短期不会变**。

| 平台 | 普通浏览器 Web Bluetooth | 采用方案 |
|------|--------------------------|----------|
| PC（Win/Mac/Linux） | ✅ Chrome / Edge | 直接用本站网页 |
| Android | ✅ Chrome | 直接用本站网页 |
| iPad / iPhone | ❌ 完全不支持 | **用 [Bluefy](https://apps.apple.com/app/bluefy-web-ble-browser/id1492822055) 特殊浏览器打开本站**（免费，自带蓝牙栈，同一套网页代码即可用） |

> ✅ 已与用户确认：iOS 端走 **Bluefy 浏览器**。好处是**一套 Web Bluetooth 代码四端通用**，iOS 只是换个浏览器打开，无需写原生 App / 小程序。

### 2. 【核心约束】发货码是"图片"，不是"可编码的文本"
代码扫描确认（见 `webside/src/views/Todos/`）：
- 页面**没有任何 QR/条码生成库**（无 `qrcode`、`jsbarcode`）；
- 「已打包」发货码来自 Mercari，存为 **图片**：字段 `qr_image_path`（列表缩略图/全屏查看）、`qr_image_url`（详情弹窗），经 `mercariImageUrl()`（`webside/src/utils/mercariImage.js`）解析为后端代理 URL 或本地 `/imges/...`；
- 前端**只有图片，拿不到二维码里的原始字符串**。

**推论**：不能用 TSPL 的 `QRCODE`/`BARCODE` 指令（那些需要原文），必须把图片**光栅化成 1-bit 单色位图**，用打印机的**图形/位图指令**（TSPL `BITMAP` / ESC-POS 光栅 / CPCL 图形）发送。这带来**清晰度风险**（见第五节风险）。

### 3. 【德佟侧】型号 = P2（便携手持热敏机）+ 官方 SDK 是原生插件
✅ 已确认型号为 **德佟 P2**，实测规格（[技术参数表](https://www.dehsm.com/download/22094.html)）：

| 参数 | 值 |
|------|-----|
| 打印分辨率 | **203 DPI（= 8 dots/mm）** |
| 装纸/标签宽度 | **20 ~ 55 mm** |
| 可打印宽度（点数） | 约 **384 dots ≈ 48 mm**（便携机常见值，**以实测为准**） |
| 打印方式 | 热敏（无墨无碳带） |
| 连接 | 手机蓝牙（便携机基本为 **BLE**，正合 Web Bluetooth） |
| 机身/电池 | 128×86×62mm / 249g / 1500mAh×3.7V / Type-C 充电 |

**对方案的影响：**
- P2 是**便携手持机**。这类小型 BLE 打印机的指令集**多为 CPCL 或 ESC-POS 光栅**，TSPL 反而更常见于 DP 系列台式标签机 —— 因此 P2 的指令后端**优先试 CPCL / ESC-POS 光栅，其次 TSPL**（与台式机相反，**最终以 spike 实测为准**）。
- 德佟官方给的是 [uni-app 原生插件（LPAPI）](https://ext.dcloud.net.cn/plugin?id=1901)，**只能在原生 App 里用，网页里调不了**。所以网页方案要**自己拼指令 + 走 Web Bluetooth GATT**。
- 203 DPI + 48mm 宽是个**较小的打印面**，二维码光栅化后模块偏小，**清晰度风险更突出**（见第五节 ②），务必按 203 DPI 整数倍缩放。

## 二、总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  /#/todos 页面（已打包发货码）                                  │
│   [打印] 按钮  →  拿到图片 URL (qr_image_path / qr_image_url)   │
└───────────────┬─────────────────────────────────────────────┘
                │
        ┌───────▼────────┐   图片 → <canvas> → 缩放到标签点宽
        │  光栅化模块      │   → 二值化(阈值) → 打包成 1-bit 位图
        │  rasterize.js   │   （复用现有 captureAndPushFrame 的 canvas 写法）
        └───────┬────────┘
                │  位图字节
        ┌───────▼────────┐   按配置选指令后端：
        │  指令封装        │   TSPL(默认) / ESC-POS / CPCL
        │  commands/*.js  │   SIZE/GAP/DENSITY/CLS/BITMAP/PRINT (+可选文本行:订单号)
        └───────┬────────┘
                │  指令字节流
        ┌───────▼────────┐   navigator.bluetooth.requestDevice
        │  蓝牙连接管理    │   → GATT connect → 写特征值（分片，避开 MTU 上限）
        │  connection.js  │   配置: serviceUUID / writeCharUUID / 指令集 / DPI / 标签尺寸
        └────────────────┘
```

新增前端模块（不引第三方 SDK，纯 Web Bluetooth）：
```
webside/src/utils/btPrinter/
├── index.js          # 对外 API: printLabelImage(url, options)
├── connection.js     # 设备连接/重连/断开、服务发现、分片写入

├── config.js         # localStorage 读写: UUID/指令集/DPI/标签宽高/浓度
└── commands/
    ├── tspl.js       # 德佟默认，BITMAP 位图指令
    ├── escpos.js     # 备选，GS v 0 光栅
    └── cpcl.js       # 备选
```

## 三、关键技术点

### 3.1 前提条件（硬性）
- **必须 HTTPS（安全上下文）**：dev 已通过 `@vitejs/plugin-basic-ssl` 满足（https://localhost:9600）；**生产环境也必须 HTTPS**，否则 `navigator.bluetooth` 为 undefined。
- **必须用户手势触发**：`requestDevice()` 只能在点击等用户事件里调用，不能自动连接。
- **可用性探测**：`if (!navigator.bluetooth) { 提示当前浏览器不支持，iOS 请用 Bluefy }`。

### 3.2 连接与服务发现（应对"型号未定"）
由于型号/UUID 未知，首连流程：
```js
const device = await navigator.bluetooth.requestDevice({
  acceptAllDevices: true,
  // optionalServices 必须预先列出，否则连上也访问不到该服务
  optionalServices: [
    0xff00, 0x18f0, 0x49535343 - 0, // 常见打印服务(示意)
    '0000ff00-0000-1000-8000-00805f9b34fb',
    '000018f0-0000-1000-8000-00805f9b34fb',
    '49535343-fe7d-4ae5-8fa9-9fafd205e455', // ISSC/BLE透传
    '6e400001-b5a3-f393-e0a9-e50e24dcca9e', // Nordic UART
  ],
});
const server = await device.gatt.connect();
// 发现并打印全部服务/特征，帮用户填配置（首次调试关键！）
const services = await server.getPrimaryServices();
for (const s of services) {
  for (const c of await s.getCharacteristics()) {
    console.log(s.uuid, c.uuid, c.properties); // 找 write / writeWithoutResponse 的那个
  }
}
```
> **调试面板**：做一个「打印机设置」弹窗，连上后把服务/特征列表显示出来，用户挑出可写特征，保存进 `config.js`。之后按配置直连，无需再发现。

### 3.3 图片光栅化（清晰度是成败关键）
```
图片URL (mercariImageUrl(qr_image_path))
  → new Image() 加载（注意 CORS：本地 /imges 与后端代理同源，OK）
  → drawImage 到 <canvas>，缩放到 = 标签可打印点宽（标签尺寸由用户手动输入）
       P2：203 DPI(8 dots/mm)，可打印宽 ≈ 384 dots(48mm)
       当前标签 30×30mm → 30×8 = 240×240 dots（每行 30 字节 × 240 行）
  → getImageData → 灰度 → 阈值二值化(如 <128 视为黑)
  → 按行打包成字节（每 8 像素 1 字节，宽度按 8 取整补白）
```
**二维码清晰度要点**（否则扫不出来）：
- 用**打印机原生 DPI** 出图，**整数倍缩放 + 最近邻**，避免抗锯齿把码点糊掉；
- 保留**静区（quiet zone）**留白；
- 目标：让每个 QR 模块 ≥ 2~3 个打印点。
- 复用现有 canvas 写法：`webside/src/views/Todos/script.js:1376-1398`（`captureAndPushFrame` 已有 `getContext('2d')` / `toDataURL` 模式）。

### 3.4 TSPL 位图指令（德佟默认）
```
SIZE 50 mm, 30 mm      # 标签尺寸(按实际耗材)
GAP 2 mm, 0 mm         # 间隙
DIRECTION 1
DENSITY 8              # 打印浓度
CLS
BITMAP 0,0,<宽字节数>,<高点数>,0,<原始位图字节...>
TEXT 10,<y>,"3",0,1,1,"<订单号后4位>"   # 可选：打印订单号做人工核对
PRINT 1,1
```
- `BITMAP` 的 `宽字节数 = ceil(点宽/8)`；TSPL 位图里 **bit=0 为黑点、bit=1 为不打印**，二值化后通常要**取反**。
- 备选后端：ESC-POS 用 `GS v 0`（光栅位图），CPCL 用 `! ... EG ...`。

### 3.5 分片写入（避开 BLE MTU 上限）
BLE 单包通常 ≤ 20~512 字节。指令字节流要**切片顺序写**，每片之间 `await` 小延时：
```js
async function writeChunked(characteristic, bytes, chunk = 180) {
  for (let i = 0; i < bytes.length; i += chunk) {
    const slice = bytes.slice(i, i + chunk);
    // 优先 writeValueWithoutResponse（更快），不支持则 writeValue
    await characteristic.writeValueWithoutResponse(slice).catch(
      () => characteristic.writeValue(slice));
    await new Promise(r => setTimeout(r, 15)); // 给打印机缓冲
  }
}
```

### 3.6 UI 集成点（已在代码中定位）
- 「已打包」发货码列：`webside/src/views/Todos/index.vue:88-102`（缩略图旁加 **打印** 按钮）；
- 全屏发货码查看器：`index.vue:838-853`（查看器里加 **打印** 按钮，`qrViewer.src` 即图片、`qrViewer.orderNo` 即订单号）；
- 详情弹窗发货码块：`index.vue:353-380`；
- 新增「打印机设置」入口（建议放系统设置或一个独立弹窗）：连接 / 测试打印 / 服务发现 / 保存配置。

## 四、分阶段实施计划

> ✅ **阶段 0 实测结论（2026-07 真机验证）**：P2 吃 **ESC-POS 光栅指令（`GS v 0`，测试 B）**，
> TSPL / CPCL 不采用。可写特征 UUID 未记录 → 正式模块保留**自动服务发现**，
> 首连自动选中第一个可写特征并持久化到 localStorage，设置面板可手动切换。
> 正式模块只实现 ESC-POS 后端（其余指令集留在 `bt-spike.html` 供诊断）。

| 阶段 | 内容 | 验证标准 |
|------|------|----------|
| **0. Spike（最先做，去风险）** | 拿真实德佟打印机：`requestDevice` 连上 → 打印服务/特征列表 → 硬编码发一段 TSPL `BITMAP` 试打一张固定位图 | ✅ 已完成：ESC-POS 位图（测试 B）打印成功 |
| **1. 连接管理** | `connection.js`：连接/断开/重连、服务发现面板、分片写入 | 能列出服务、稳定写入 |
| **2. 配置** | `config.js` + 「打印机设置」UI：UUID / 指令集 / DPI / **标签宽高（用户手动输入 mm，默认 30×30）** / 浓度，存 localStorage | 保存后能按配置直连 |
| **3. 光栅化** | `rasterize.js`：图片 URL → 1-bit 位图，QR 友好缩放 | 本地预览位图清晰、模块不糊 |
| **4. 指令封装** | `commands/tspl.js`（先做 TSPL）+ ESC-POS/CPCL 备选 | 生成的指令能驱动打印 |
| **5. 页面集成** | 在三个 UI 点加「打印」按钮，串起 拉图→光栅→发送 | todos 页一键打印发货码 |
| **6. 各端联调** | PC Chrome/Edge、Android Chrome 原生；iOS 用 Bluefy 打开验证 | 四端都能打印；写一页操作说明（尤其 iOS 装 Bluefy 步骤） |

## 五、主要风险与对策

| 风险 | 说明 | 对策 |
|------|------|------|
| **① 该型号是否吃裸 TSPL** | 德佟官方走原生插件，未公开确认裸 TSPL over BLE 一定可用 | **阶段 0 spike 先验证**；不行则试 CPCL/ESC-POS；都不行则该型号只能走原生 App（破坏"纯网页"目标） |
| **② 二维码光栅化后扫不出** | 图片降采样糊掉码点 | 原生 DPI 整数倍缩放+最近邻、留静区、每模块≥2~3点；提供打印预览 |
| **③ 型号/UUID 未定** | 无法硬编码 | 服务发现面板 + 可配置，已纳入方案 |
| **④ iOS 体验** | 必须装 Bluefy，用户教育成本 | 写清操作指引；页面检测到 iOS Safari 时提示"请用 Bluefy 打开" |
| **⑤ 生产 HTTPS** | 非 HTTPS 下蓝牙 API 不存在 | 部署强制 HTTPS |
| **⑥ 标签尺寸/耗材** | 发货码需可被便利店/邮局扫描 | 标签宽高、浓度做成可配置，按实际耗材调 |
